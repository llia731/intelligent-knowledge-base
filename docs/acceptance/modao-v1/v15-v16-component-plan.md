### 状态机与闭环

下列异常/加载属于实现建议，正常态布局以截图为准：

- `closed → loading-existing → editing`；打开从当前文档和已存分享设置初始化新草稿，不复用上次其他文档的临时值。
- `editing → validation-error`：指定部门为空、文档不存在等，错误靠近字段；关闭/取消不写库，重新打开回到已保存值。
- `editing → saving → saved`：一次提交范围、有效期、摘要与密码；保存中禁用重复提交；只有服务确认后才更新链接和成功状态、记录审计。
- `saving → error → retry`：保留草稿，展示错误，不关闭窗口、不显示假成功。
- `saved → copying → copied/copy-error`：调用真实 Clipboard API 后才能提示已复制；链接不可用时禁用复制和渠道按钮。
- `saved → revoking → revoked/error`：撤销成功才使旧链接失效；前端移除 URL 不能替代真实撤销。
- 当前本地演示阶段可完成外观、表单和草稿，但缺少服务时用明确不可用状态，不生成看似真实的可访问链接。“保存分享附言”通过不等于原型分享闭环通过。

验收：匹配672×820和所有字段/按钮；鼠标、Tab和Escape可用；范围切换不串文档；取消不保存；错误不丢草稿；复制失败不报成功；真实服务接通后另验密码/到期/范围/撤销，不连接生产数据作为 UI 验收前提。

### 状态与数据设计建议

- `closed → opening → editing(tab)`：从已保存 profile/preferences 克隆到一个 draft；切页签保留草稿，不自动提交。
- 姓名/部门/头像用受控字段；保存时验证姓名和部门的有效值，显示本字段错误。具体长度上限、是否允许空部门为原型未规定内容，实施时遵循已有业务规则，不凭截图新增阻断规则。
- `editing → saving → saved/failed`：原子提交所有页签；失败保留草稿并允许重试；成功关闭并更新账户展示。取消、关闭、Escape 丢弃这次未保存草稿，不偷偷写入偏好。
- 鼠标点击、焦点环、页签箭头键、单选/复选键盘和开关均可用；不得重现 B01 的遮罩拦截。个人资料保存必须继续通过现有 PR11 回归脚本。
- `src/lib/kb/types.ts` 拟增加：`AvatarKey`、`AppearancePreferences {theme, defaultLayout, compactSidebar}`、`SearchPreferences {mode, sort, pageSize, expandSynonyms}`、`NotificationPreferences {channels, frequency}`；实际枚举严格来自上表。
- `src/lib/kb/store.ts` 拟增加 `personalPreferences` 和一次性 `savePersonalSettings`，保留 `saveProfile` 的兼容调用；旧版本只补缺字段，不重置已有名称/部门、文档、审核或 ACL。继续保留 freshSecret 排除和旧值落盘清理，偏好迁移不能把旧密钥带回。
- 不把演示角色切换混入四页签原型内容：开发期可独立保留现有演示入口，正式展示位置属于产品/调试策略。个人设置不能改变服务端身份或权限。
- 主题、布局与紧凑侧栏建议保存后应用，取消回滚；是否提供即时预览并未由截图证明，先不增加额外预览机制。通知渠道只保存设置，不自动发短信/邮件或接入真实通知服务。

## 建议实施顺序与完成标准

1. 先做共用容器及 V16 四页签静态结构，按9态截图逐一核对；不改账户/权限/模型业务。
2. 接入受控草稿、保存/取消及旧状态兼容；个人中心鼠标保存/刷新及 B05 迁移回归必须一直为绿。
3. 实现 V15 各字段和状态，保留现有附言作为摘要兼容数据；接可用的分享服务适配器前，真实链接能力不得报成功。
4. 按同字体、1920×1080、DPR1、同草稿和同默认项做9态截图回归，再补选中/取消/错误/加载截图。原生字体另列验收，不以替代字体相似代替原字形签收。
5. 核对组件几何、图标、边框/填色、文字和控件状态，审计共享 `.modal` 是否受影响；无需推倒重做整套前端。
