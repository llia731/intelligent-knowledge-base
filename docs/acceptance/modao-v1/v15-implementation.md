# V15 知识分享弹窗：实现与回归门槛

基线：PR #12 head `d51c7f193fad95b55de49396a7603d9643f2d703`，V16 核心 15/15、PR #11 核心 6/6（由 Codex Cloud 独立验证）。

原型依据：`docs/acceptance/modao-v1/v15-v16-component-plan.md`，原始 ZIP 及视觉证据。

## 已实现的范围

- 知识管理“分享”入口现在使用独立的 Radix 对话框，不干扰查看、编辑及个人中心。
- 1920×1080 视口中对话框宽 672px、高 820px，以主内容区为水平中心；窄视口滚动适配。
- 链接开关、范围（全员、指定部门、仅自己）、部门选择、内存中密码草稿、有效期（7、30、90 天及永久）、只读链接区域、渠道按钮和推荐摘要。
- 密码只保存在当前对话框的 React 草稿状态，关闭时清空，不写入 Zustand、localStorage 或审计记录。
- 当前本地演示仍可点击“保存推荐摘要”，调用原有 `shareDoc`，在刷新后保留摘要；不是创建真实分享。取消、Escape 或点击遮罩丢弃未保存摘要。
- 原型所示默认部门只有“产品研发部”得到确认；不虚构部门列表或跨部门授权。
- 未接入分享服务之前，不创建具有误导性的可访问 URL；“复制链接”、渠道发送、确认分享均不可用，原生 title 和文本说明原因。

## 尚未实现

- **真实分享服务**：创建、撤销、密码校验、有效期、范围鉴权、链接复制及渠道分发，必须由受控服务端 API 返回可靠结果后再启用。
- 暂不持久化范围、开关、有效期和部门；这些仅作为 UI 草稿。推荐摘要保留既有本地存储语义。
- 新版原型未规定失败重试、密码规则及部门真实数据来源；不得凭空设定为产品业务规则。
- PingFangSC 原生字体仍缺失，严格像素签收需要可用字体或明确批准替代字形。

## Codex Cloud 验收门槛

在现有云环境检出本分支，确认 Commit。执行 `npm run typecheck`、`npm run build:dev`，以及已有 PR #11 6 项、V16 15 项回归，保证 V15 没有破坏既有流程。

新增 Playwright 用例（独立 browser context、同 1920×1080，DPR1、Noto Sans CJK SC 结构比对）：

1. 从知识管理列表点击“分享”，检查 672×820 框及原型全部字段，保存对照截图及 DOM 锚点。
2. 检查链接默认关闭、范围默认全员、有效期默认 7 天。
3. 切换到指定部门，验证部门选择可用；切换其他范围，不应保存伪访问授权。
4. 输入访问密码，关闭及刷新后内存/持久化均无明文；验证没有日志泄露。
5. 有效期下拉覆盖 7、30、90 天、永久。
6. 未连接分享服务时复制、渠道和确认分享不可操作；不得产生 URL 或“已分享”日志。
7. 编辑推荐摘要，取消后刷新不保存；重新编辑并点“保存推荐摘要”，刷新后摘要保留且不产生分享链接。
8. 点击关闭、Escape、遮罩均能退出；焦点恢复至原分享入口；键盘 Tab 不逃离弹窗。
9. 切换不同文档时，摘要不能串文档，密码临时值必须重置。
10. 复查知识管理查看、编辑、删除、回收站及 14 个默认页面路由截图至少不回归。

提供独立报告、原型 V15 与 React V15 并排截图、几何对照、失败原始日志和回归脚本；如果发现偏差，先在当前分支最小修复、再复测。保持 Draft，不合并 main。
