# 墨刀 V1.0 原型包结构核验与产品页面映射

核查时间：2026-11-04。来源：用户在会话中直接上传的 `智能知识库V1.0(1).zip`，与 GitHub `prototype/智能知识库V1.0.zip` 的记录大小一致（15,462,702 字节）。**仅凭文件大小一致不能证明字节完全相同**，正式验收前应比对 SHA-256。

## 一、原型内容形式与证据范围

- 实际是墨刀导出的**离线交互原型包**，有 `index.html`、`mb-proto2/` 运行资产与 `extra/data.1.js` 中的页面和组件数据；不是逐页 PNG 截图，也不是源代码产品工程。
- 通过解码 `data.1.js` 的压缩原型对象，已经确认两个产品分组：**智能知识库用户端**、**平台后台管理**。
- 共确认 14 个以 `page-0` 标识的明确命名业务页面；另有两个名为“画布 8”的画布节点，**不作为正式需求页面**，除非后续人工核对证明应纳入。
- 本轮抽取的是原型内部的页面树、元素名称与部分界面文案。**尚未运行离线原型逐一点击检查交互**，因此不能将所有按钮名称直接推定为完整可用的交互逻辑，也不能声称已逐屏完成视觉验收。
- ZIP 内存在许多通用设备图片和客户端运行资源，这些不属于产品需求资产。

## 四、发现的实现差异

1. **模型选择**：墨刀“AI问答”页面具有模型选择下拉元素；当前 `ask.tsx` 已有 AI 助手选择，但实际 `ask.functions.ts` 将生成模型固定为外部 `grok-4.5`。需要将模型选择映射到可用的内网模型，并确认哪些原型展示名称只是占位。
2. **知识上传**：上传组件不能用 `file.text()` 实现 PDF 和 Office 解析，且固定间隔定时器不能作为真实工作进度；需要 MinerU API、任务表和错误恢复。
3. **智能检索**：本地字符二元组评分与“相似度”展示不是 BM25 或 Dense 真实分数；需要服务端安全检索及准确解释结果。
4. **鉴权**：演示角色切换、浏览器 localStorage 不足以支撑正式知识权限；可复用已有 Better Auth 代码和业务迁移框架。
5. **引用定位**：原型有“回答来源与引用”，现有 Citation 类型缺失文档版本及页码等定位信息，需配合 MinerU 的真实结果能力补齐。

## 五、仍需人工确认的具体事项

1. 两个“画布 8”是否仅为辅助设计稿，还是属于需要交付的产品界面。
2. “AI问答”模型下拉的展示名称是否需要与实际可用内网模型保持一致（例如原型的 GPT-4、Claude 等是否为演示名称）。
3. 本地用户管理的身份系统：沿用现有 Better Auth 独立账号，还是接入单位的统一身份认证。
4. 上传和审核的先后约束，尤其“受限知识是否先入库解析再审核”与索引可见性；应以实际点击原型或正式产品说明为准。
