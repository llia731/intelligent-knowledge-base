# 智能检索：原型结构和分页首轮修复

**基线：** PR #15 最终验证提交 `2d0c297410adfd2dbcafd7daaa48f0b00505fda7`，Codex Cloud 报告 53/53 浏览器回归，TypeScript 和开发构建通过。

**原型证据：** `docs/acceptance/modao-v1/visual-audit.md`，14 页源图证据中的 `search` 页面。原始报告明确指出：高级语法属于横向搜索卡片，而当前 React 将其放在左侧筛选栏；知识库多选、类型、标签、分类、时间及结果操作存在缺口。

## 原 PR 首轮修改（独立验收前）

- 搜索模式、关键词、建议和高级语法放入同一个横向区域，避免将语法视为侧栏过滤器。
- 高级语法标签仍仅填入查询框；**没有宣称本地检索引擎实际支持复杂语法解析**。
- 搜索结果与原型示例均实行真正的每页 4 条切片；末页禁用下一页，首轮禁用上一页；查询、模式、知识库范围及排序改变时重置页码。
- 不再声称尚未执行的搜索存在“128 条真实结果、耗时 0.34 秒”；明确区分本地实际结果与原型示例。
- “导出”明确显示当前未生成文件，不伪造复制、生成或下载成功。

## 当前能力限制

- 多知识库、文件名类型、已存分类路径及日期等本地筛选已经复核；独立标签、问答实体及正式企业元数据模型仍未实现。
- 向量检索、混合召回、语法解析、相似度实值和服务端排序尚未接通。现有模式仍沿用本地已有逻辑；严禁将其表述为真实向量能力。
- 已验证本地正文查看与真实剪贴板；反馈、原文件导出和批量下载未接服务，明确禁用。界面验收不代表业务能力完成。
- 独立验收的类型、构建、回归和中间异常详见文末报告；仍需人工视觉复核及未定义产品行为确认。

## 原定 Codex Cloud 回归范围（本轮已执行）

1. 检出 PR 分支并核对基线；执行 `npm run typecheck`、`npm run build:dev`。
2. 运行 PR #15 的原 53 项浏览器用例（B01/B02/B03/B05、V15、V16、知识管理）。
3. 对原型和 React `/search` 各采一张 1920×1080、DPR 1、相同字体和测试数据的截图，测量查询卡、语法条、筛选栏和结果卡位置。
4. 专项验证分页：本地真实结果 0、1、4、5、9 条；第一页、末页、筛选收缩时不会错页；点击后实际列表发生变化。
5. 验证切换模式、排序、范围重置页码，禁用状态正确，搜索次数与审计轨迹不因分页跳转虚增。
6. 核实原型高级语法功能的真实支持程度。若本地无法解析 `title:` 等表达式，应保留示例输入与明显说明，不得将无结果误报为完整语法支持。
7. 对真实图标、结果操作、筛选字段进一步采集原型 DOM 和 SVG 资源，能够无歧义还原的直接在此分支修复。
8. 严格区分因初始 SSR 和 hydration 未完成导致的截图与业务错误，复用上一轮 `data-app-ready` 就绪标记，保留原始失败日志，不删除断言。
9. 提交原型与 React 对照、源码修复、独立测试报告及仍未实现功能表；不连接生产模型服务，不修改 main 或合并 PR。

**验收范围：** 本轮优先核实“横向语法区与真实分页”，之后再逐项修复其余原型差异。
