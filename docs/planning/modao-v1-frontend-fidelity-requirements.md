# 墨刀 V1.0 前端严格复刻要求（业务方已确认）

确认日期：2026-11-04

## 一、不可变更的业务要求

**墨刀《智能知识库 V1.0》是最终前端设计基准，不只是功能参考。**

- 保留 React、TanStack Router、现有服务端及可复用业务逻辑，但页面必须按墨刀原型设计还原。
- **禁止开发者自主改版**：不得将原型布局改为当前自创的深色侧栏、暖色大背景、大字号衬线风格等，除非逐项证明与原型一致，或业务方批准设计变更。
- 不得以“页面存在”“功能名称一致”“大致相似”代替视觉与交互验收。
- 任何产品设计差异都要有原型节点证据、截图对照和明确的处理状态；未确定的原型元素不擅自删除或改写。
- 已获业务确认的例外：**保留墨刀 AI 问答的模型选择交互，模型选项改为服务端内网实际可用生成模型的动态列表**。详见 PR #6 的 ADR-0002。

## 二、还原范围

对上传的墨刀离线 ZIP 完整核对，至少覆盖：

**用户端**：首页、知识上传、智能检索、AI 问答、知识管理、权限设置、审计日志。

**后台**：总览仪表盘、用户管理、角色权限、知识库配置、内容审核、系统日志、API 密钥。

另有两个名为“画布 8”的节点，暂标记待核定，不能静默认定为业务页面，也不能无证据删除。

逐页面登记：画布设计尺寸、导航结构、顶部栏、内容区栅格、字体、字号、行高、颜色、边框、间距、图标、图片资产、控件状态、空状态、加载与错误状态、模态弹窗、抽屉、点击跳转及反馈行为。

## 三、验收规则

1. 原型离线包的**实际渲染画面**作为视觉基准。单靠解码节点名称不能宣称高保真还原。
2. 同一浏览器视口、页面状态、数据条件下生成“墨刀基准截图”和“React 实现截图”，逐页人工目视核对并采用图像差异辅助检查。
3. 必须记录页面与关键组件、弹窗、操作结果的对应关系；页面打开成功不等于交互验收通过。
4. 原型的真实显示文本、图标、对齐关系、交互路径原则上不改；与业务方已确认的新模型动态列表冲突时，按批准的例外实施。
5. 视觉误差阈值不能在未获取真实基准截图前随意承诺具体百分比；形成基线后再定义可客观复现的截图比对要求和人工判定标准。
6. 不得为了表面视觉一致牺牲服务端鉴权、实际权限过滤、可信检索和秘钥安全；后端升级与 UI 复刻应独立组织任务、并行推进。
7. 只有 **原型设计逐页面复核、关键交互验收、自动化构建测试** 都通过后，前端复刻任务才能标记完成。

## 四、实施顺序

1. 从已上传 ZIP 解包原型，在浏览器运行离线预览，提取全部设计画布与关键状态，并保存截图及尺寸信息。若离线原型运行受限，需先解决渲染问题，不以臆测的视觉样式开发。
2. 为 14 个正式命名页面建立逐屏矩阵，标注截图、路由、组件、差异、验收状态。
3. 优先改造公共外壳（导航、头部、主题变量、字体、页面容器、弹窗、表格和表单），禁止只局部换色。
4. 逐页面替换布局和 UI，并保留可复用的状态及业务逻辑，尽量避免大规模推倒重写。
5. 对比截图、修复视觉差异和交互差异，完成业务方逐页面确认。
6. 同步跟进 RAG 真实后端，不得因为当前演示数据可渲染就声称企业级知识库已经上线。

## 五、现阶段判断

现在 152 上部署的版本已通过构建、HTTP 可访问，**但仅能作为当前实现的对照环境**，绝不能据此宣称达到墨刀 V1.0 视觉还原要求。PR #6 只实现模型动态选择基础功能，并非完整 UI 复刻。不得擅自将未验收的界面变更合并到 main。
