业务要求：**严格复刻原型，不接受仅名称或功能相近的重新设计**。来源为用户上传的 `智能知识库V1.0(1).zip`；本表只记录已确认事实，不推定未成功渲染的界面。

## 一、提取结果

运行：`python scripts/modao-inventory.py "智能知识库V1.0(1).zip" --output modao-inventory.json`。

本次已在原始 ZIP 上验证脚本：总计 **16 个 page-0 画布节点**，其中 **14 个明确命名的业务页面**，另外两个名称均为“画布 8”，用途待确认。用户端和平台后台两个页面分组已确认。

**重要：墨刀内部画布尺寸采用未解码的字符表达**，不能将其当作 px 像素值。仅凭内部图层树，无法确定视觉坐标、间距、字体和实际交互。不得在没有基准截图的情况下标记“严格复刻完成”。

## 三、截图提取操作规范

1. 将墨刀 ZIP 在受控本地目录解压，在其 `index.html` 所在目录运行 HTTP 静态服务。**不能把预览器的黑屏或浏览器错误页当作设计基线**。
2. 在浏览器中检查离线原型预览器是否加载，明确记录实际画布尺寸、页面切换方式、字体加载是否正常。
3. 针对每个页面，固定浏览器视口，依次采集原型默认态、关键弹窗、下拉、展开、加载、空状态和错误状态（如果原型有设计）。
4. 当前 React 页面在完全相同视口、内容条件下采集对应截图，建立一对一的基准证据。
5. 由开发者按照截图修复公共框架、组件和页面，再进行逐项视觉与交互复核。
6. 原型未定义的状态单独提出产品确认，不猜测设计。
7. 严格保留**已确认例外**：AI 问答模型选择 UI 保留，但实际模型名称通过内网模型服务动态显示。

### 本轮渲染验证记录

已在当前隔离环境中使用 `python -m http.server`、Chromium headless 尝试打开墨刀离线导出包；浏览器命令未能在限定运行时间内生成有效截图，因此没有取得可信视觉基线。该阻碍不能通过猜测颜色、像素或排版解决。

## 四、可以立即分工的工程任务

- **UI 基线采集**：建立原型截图和实际页面截图目录，并检查关键交互。
- **公共组件重构**：待基线完整后，根据截图修复导航、顶部栏、字体、颜色、间距、表格、卡片、弹窗。
- **页面开发**：按本清单逐一验收，不得只看路由是否存在。
- **自动化回归**：构建通过后增加浏览器截图测试。需要固定视口、种子数据和截图更新审批流程。
- **后端升级**：模型服务、MinerU、可信检索和 ACL 与 UI 还原分支解耦。

## 五、何时需要人工介入

只有自动渲染环境无法恢复时，需要负责人员在**能够显示原型的浏览器**中提供每页截图，或批准在可访问浏览器的受控机器执行截图脚本。其他界面实现工作应继续由开发者完成，无需业务方逐个批准 CSS 修改。
