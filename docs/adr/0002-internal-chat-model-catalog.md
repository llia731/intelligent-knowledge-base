# ADR-0002：问答模型使用内网服务端动态列表

状态：**已获产品侧确认**（2026-11-04）。本 ADR 仅确定模型选择规则，不等于生产问答链路已通过验证。

## 产品决策

- 严格保留墨刀 V1.0 “AI 问答”中的**模型选择交互**，但不把 GPT-4、Claude、文心一言、通义千问等原型示例名固定为实际生产可选项。
- 生成模型列表来自服务端配置与内网模型网关查询的交集，只展示已授权且网关当前声明存在的生成模型。
- 不能把 Embedding、Reranker 等非聊天模型显示在用户选择框中。
- 服务端在发起生成前再次校验模型 ID，不信任浏览器提交的任意模型名称。
- 若内网模型网关失败或没有符合要求的模型，应显示明确的不可用状态，不伪造示例模型。
- 模型 API Key 只放服务端环境，不提交 GitHub，不通过 React 页面或 API 响应公开。

## 第一批功能实现

- `src/lib/kb/model-catalog.server.ts`：读取管理员允许的模型 ID 列表；用内网网关 `GET /models` 获取已登记模型；两者求交集。
- `src/lib/kb/ask.functions.ts`：新增已鉴权的 `getChatModels` 服务函数，改为用选中的内部模型请求 `POST /chat/completions`。
- `src/routes/_app/ask.tsx`：增加与墨刀交互一致的“生成模型”下拉框，模型不可用时禁止发送。
- 不再调用原来固定的 x.ai `grok-4.5`。
- **重要限制**：当前候选知识片段仍由演示前端提供；正式生产部署配置 `DATABASE_URL` 时该问答服务明确拒绝调用，直到完成服务端可信检索与权限改造。该措施避免在已有不安全证据来源上直接开放正式模型问答。

## 服务端环境配置

```dotenv
IKB_MODEL_BASE_URL=http://172.16.12.3:4000/v1
IKB_CHAT_MODELS=GLM-5.3
# INTERNAL_LLM_API_KEY 请通过受保护的服务端环境注入
```

`IKB_CHAT_MODELS` 是允许列表，而不是模型连通性声明。只有网关 `/models` 返回相同 ID 后才显示该模型。实际部署前要确认 GLM-5.3 的登记 ID 与当前环境一致。

当前模型发现接口只是读取网关登记表，不代表逐个发起推理健康检查。实际模型调用仍可能由于容量、权限或网关故障失败，UI 应按真实错误提示。

## 验收测试（尚未运行）

1. 没有 `IKB_CHAT_MODELS`，UI 为空且发送禁用。
2. 网关异常或请求超时，UI 不显示陈旧的假可用模型。
3. 网关返回 Embedding 和 Reranker，但允许列表仅包含 GLM-5.3 时，只显示 GLM-5.3。
4. 构造未允许的模型 ID 提交问答，服务端拒绝。
5. 服务端向网关转发所选模型 ID，API Key 不返回客户端。
6. 正式配置 `DATABASE_URL` 时，不使用客户端传入的 contexts 调用大模型。
7. 完成服务端检索和权限链路后，另开 PR 解除生产问答保护并进行安全回归测试。

## 后续工程化事项

当前模型清单通过服务端环境配置允许列表，尚不支持墨刀后台页面中直接变更模型配置。后续应建设持久化的后台模型管理、权限控制和模型能力分类，并以服务端审计记录操作，不能将目前浏览器本地 `ResourceLink` 设置视为可信运行配置。
